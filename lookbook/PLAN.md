# AI 룩북 릴스 자동화 계획

목표: PC에서 `python run.py` 한 번 실행하면 **기획 → 상품 매칭 → 이미지·영상 생성 → 편집 → 링크 사이트 반영 → 인스타 예약 업로드**까지 끝난다.

## 1. 전체 구조

```
[사용자 PC]                                         [Cloudflare (무료 한도)]
python run.py
 ├─ ① plan      트렌드 + 과거 성과 → episode.json
 ├─ ② match     쿠팡 API로 비슷한 상품 검색 → 링크
 ├─ ③ generate  ComfyUI(로컬 GPU) API로 룩 이미지·영상
 ├─ ④ edit      자막 오버레이 + ffmpeg로 릴스 mp4
 ├─ ⑤ review    (선택) 검수 페이지 → 승인
 └─ ⑥ ship      mp4 업로드 ───────────────────────▶  R2 (공개 영상 URL)
                사이트 데이터 배포 ─────────────────▶  Pages (링크 사이트)
                예약 등록 ──────────────────────────▶  D1 예약 큐
                                                      Worker cron (매 5분)
                                                       └─ 예약 시각 → 인스타 API로 릴스 게시
                                                      Worker /go/<code>
                                                       └─ 클릭 기록 → 쿠팡/에이블리로 이동
```

**예약 게시를 클라우드가 맡는 이유**
- 인스타 API에는 예약 파라미터가 없다. 정해진 시각에 직접 "게시" 요청을 보내야 한다.
- 인스타 API는 영상을 **공개 URL**로만 받는다. 어차피 영상을 클라우드(R2)에 올려야 한다.
- 그래서 게시도 클라우드(Worker cron)가 하면 **예약 시각에 PC가 꺼져 있어도 된다.**

## 1-1. 클라우드 조사 + PC 실행 분리

조사·기획은 클라우드(Claude Code 예약 작업)가 미리 해 두고, PC는 그 결과를 받아 실행만 한다.

```
[클라우드: 매주 정해진 시각, API 키 없음]
  트렌드 조사(웹 검색) + 지난주 성과(stats/) 분석
  → plans/<주차>/<id>.json (후킹 제목, 룩, 아이템 설명, 생성 프롬프트, 캡션, 게시 시각)
  → git 커밋·푸시

[PC: python run.py, .env에 API 키]
  git pull → 아직 처리 안 한 기획안 선택
  → ② match → ③ generate → ④ edit → ⑤ review → ⑥ ship(예약)
  → 지난 게시물 성과를 stats/에 기록하고 푸시 (다음 주 조사에 반영)
```

- **비밀 정보는 PC의 `.env`와 Cloudflare 시크릿에만** 둔다. 저장소와 클라우드 조사 환경에는 넣지 않는다.
- 기획을 클라우드가 하므로 ① plan 단계는 PC에서 LLM API 없이 동작한다.
- PC의 처리 상태는 `episodes/<id>/state.json`(커밋 안 함)에 기록해서, 같은 기획안을 두 번 올리지 않는다.

## 2. 단계별 상세

| 단계 | 입력 | 출력 | 비고 |
|---|---|---|---|
| ① plan | `trends/*.yaml`, 과거 성과 | `episode.json` (후킹 제목, 룩 4~6개, 아이템, 생성 프롬프트, 캡션, 해시태그) | LLM API 사용. 성공 패턴: 상황 + 가격 + 계절 + 체형 |
| ② match | 아이템 설명 | 아이템별 상품명·가격·제휴 링크, `match: similar` | 쿠팡 Open API. 에이블리는 공개 API가 없어 수동 입력 |
| ③ generate | 룩 프롬프트 + 얼굴 앵커 | `media/lookN.png/mp4` | ComfyUI의 "API 형식으로 저장" 워크플로우 JSON 사용 |
| ④ edit | 룩 영상, 후킹 제목 | `reel.mp4` (1080×1920, H.264/AAC), `cover.jpg` | 자막은 HTML 템플릿 → PNG → ffmpeg 합성 |
| ⑤ review | 전체 결과 | 승인/수정 | 로컬 웹페이지. `--auto` 옵션이면 건너뜀 |
| ⑥ ship | 승인된 에피소드 | R2 영상, 사이트 갱신, 예약 큐 등록 | 완료 알림(텔레그램/디스코드) |

각 단계는 결과를 `episode.json`에 기록한다. 중간에 실패하면 **실패한 단계부터 다시 실행**한다(예: `python run.py --from generate`).

## 3. 폴더 구조

```
lookbook/
├─ run.py                 # 한 번에 실행
├─ config.yaml            # 업로드 시간대, 얼굴 앵커, 템플릿 등
├─ .env                   # API 키 (커밋 금지)
├─ pipeline/
│  ├─ plan.py  match.py  generate.py  edit.py  review.py  ship.py
├─ comfy/workflow_api.json
├─ overlay/               # 자막 HTML 템플릿
├─ episodes/<id>/episode.json, media/
├─ trends/
├─ site/                  # 링크 사이트 생성기
└─ cloud/                 # Cloudflare Worker (예약 게시, 클릭 추적, 토큰 갱신)
```

## 4. 법·정책 준수 (자동으로 들어감)

- 링크 사이트 최상단과 캡션에 쿠팡파트너스 대가성 문구
- "이미지는 AI로 생성되었으며 판매 상품은 비슷한 스타일의 추천 상품입니다" 표시
- 영상 안에 "AI 생성" 표기, 인스타 프로필의 "AI로 생성한 프로필" 표시 유지
- 쇼핑몰 이미지는 수집·학습하지 않음 (트렌드는 텍스트 키워드만)
- 인스타 비공식 자동화 도구(instagrapi 등)는 쓰지 않음. 계정 정지 위험 때문에 공식 API만 사용

## 5. 알려진 한계

- **트렌딩 음악을 API로 붙일 수 없다.** 무료·라이선스 음원을 영상에 넣어 올리거나, 음악 없이 올린다. 도달률에 영향이 있을 수 있다.
- 인스타 API 게시 한도는 24시간에 수십~100건 (문서마다 다름. 하루 1~3개면 문제없음).
- 쿠팡 Open API는 승인 조건이 있을 수 있다. 안 되면 ② 단계를 반자동(후보 검색 → 수동 링크)으로 대체한다.
- 상품 매칭을 완전 자동으로 하면 엉뚱한 상품이 걸릴 수 있다. 처음에는 ⑤ 검수를 켜 두는 것을 권장한다.

## 6. 개발 순서

위험이 큰 연동(인스타 게시)을 먼저 검증한다.

1. **업로드 경로 검증:** 테스트 영상 1개 → R2 → 예약 큐 → 인스타 자동 게시
2. **링크 사이트 + 클릭 추적:** `episode.json` → 사이트 페이지, `/go/` 기록
3. **편집:** 자막 템플릿 + ffmpeg 합성
4. **ComfyUI 연동:** 사용 중인 워크플로우를 API JSON으로 받아 배치 실행
5. **상품 매칭:** 쿠팡 API
6. **기획 자동화:** LLM 기획 + 과거 성과 반영
7. **추가:** 댓글 → DM 자동 링크 발송, 주간 성과 리포트
